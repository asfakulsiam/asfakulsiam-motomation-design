# Required /critique Output Format

When `/critique` is used, the response **must** follow this exact structure.  
Vague paragraphs are not accepted.

```markdown
CRITIQUE — <project name or page>

### Motion Inventory
- <element or section>: Tier <1-5> — <one-line reason it exists>
- ...

### Restraint Check
- Animations considered and rejected:
  - <idea> — rejected because <reason>
  - ...

### Tier Discipline
- Highest tier used: <1-5>
- Justification: <one clear sentence>
- Any tier that feels higher than needed? <yes/no + why>

### Signature Move
- The one signature move of this site/page is: <specific description>
- Is it memorable and unique? <yes/no>

### Failure Modes
- prefers-reduced-motion: <what the user sees instead>
- Mobile: <what changes>
- Low-end device: <what changes>

### Scores (0-10)
- Originality: <score> — <one line why>
- Restraint: <score> — <one line why>
- Craft: <score> — <one line why>
- Overall: <score>

### Top 3 Concrete Fixes
1. ...
2. ...
3. ...
```

If the agent cannot fill the Signature Move or Restraint Check sections honestly, the skill is not being followed correctly.
