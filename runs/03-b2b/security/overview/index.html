Cargoline Technical Security Architecture

VERSION 4.2 • APPROVED

1. Executive Summary & Scope

Cargoline processes commercial freight shipping manifests, vessel telemetry, customs entry data, and purchase order identifiers on behalf of mid-market and enterprise importing organizations. This document details the technical and administrative controls implemented across the software lifecycle to preserve data integrity and prevent unauthorized disclosure.

2. Encryption Architecture

Data transmission between customer web browsers, API clients, carrier gateways, and Cargoline application clusters is strictly restricted to TLS 1.3 encryption. Older protocols (TLS 1.0, TLS 1.1) are explicitly rejected at network edge routers.

All persistent data stores, database volumes, backups, and message queues are encrypted at rest using AES-256 with keys managed through hardware security modules (HSM) certified under FIPS 140-2 Level 3. Encryption keys undergo automated cryptographic rotation every 90 days.

3. Data Segregation & Tenant Boundaries

Customer data is logically partitioned utilizing database Row-Level Security (RLS) policies. Every application query carries authenticated tenant context. Container records, bills of lading, and tariff classifications belonging to one importer are cryptographically segregated and completely inaccessible to other platform participants.

4. Incident Response & Business Continuity

Cargoline maintains warm cross-region database replicas with automated failover capabilities. The Recovery Point Objective (RPO) is under 5 minutes, and the Recovery Time Objective (RTO) is under 60 minutes for core tracking telemetry pipelines. External penetration tests are executed annually by CREST-accredited testing firms.
